# Changelog

**The [GitHub Releases page](https://github.com/robbeverhelst/unifi-reactor/releases) is this project's changelog.** There is no hand-maintained list of changes in this file, and that is a deliberate decision rather than an omission.

## Why

Release notes are generated by CI from the commits in each tag (`generate_release_notes: true` in `.github/workflows/release.yaml`), which is why [conventional commits](CONTRIBUTING.md#commits-and-prs) are required. That gives one source of truth — the commit history — instead of two that drift apart. A hand-written changelog in a repository this size is a file people forget to update and reviewers forget to check, and a stale changelog is worse than none: it is confidently wrong.

Image and chart versions always move together, so a single release entry describes the whole thing.

## Finding what changed

```sh
gh release view v0.3.0 --repo robbeverhelst/unifi-reactor
gh release list --repo robbeverhelst/unifi-reactor
```

Or compare two tags directly: `https://github.com/robbeverhelst/unifi-reactor/compare/v0.2.0...v0.3.0`.

## Breaking changes

The API group is `v1alpha1` and the project is pre-1.0, so breaking changes happen between minor versions. They are never silent:

- the commit is marked `!` (`feat!:`, `fix!:`) and explains the migration,
- the release notes carry an explicit upgrade section describing what changes for an existing install and how to keep the old behaviour where that is possible.

Generated notes alone are not considered sufficient for a change that alters the behaviour of an existing installation — those get written prose in the release.

## Upgrading

Read the release notes for **every** version between the one you are on and the one you are moving to, not just the newest. Two specific hazards are documented in the troubleshooting guide:

- [the first upgrade from chart 0.3.0 or earlier adopts the CRD into the release](docs/troubleshooting.md#6-the-crd-invalid-ownership-metadata-or-a-stale-schema) — the chart does it for you on that one upgrade, after which `helm upgrade` keeps the schema current on its own
- [changes to reversal semantics](docs/troubleshooting.md#4-onexit-fired--or-did-not--when-you-did-not-expect-it) affect Automations that omit `onExit`
